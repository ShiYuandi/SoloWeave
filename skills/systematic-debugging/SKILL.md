# 故障排查

1. 读取报错、复现步骤、相关代码与现有测试；先核对项目记录和 Git，避免把旧交接中的猜测当作当前事实。
2. 尽量建立能稳定失败的最小复现或检查。无法复现时记录环境和现象，继续收集证据；不要直接宣布根因。
3. 沿数据或调用路径定位原因，比较近期改动和已有实现。明确区分观察、假设与已证实的结论。影响多个模块时先缩小范围。
4. 修复确认的原因，保持改动范围适度。适合自动化回归的错误补上能在修复前失败、修复后通过的测试；不为一次性或不可稳定复现的问题写只重复实现的测试。
5. 重跑复现与受影响测试，说明实际命令及结果。未能运行时说明限制和残余风险。重要修复完成后用 `project-continuity` 记录现象、原因、变更、验证和后续观察事项；若未安装该 Skill，直接更新项目已有的交接文档。

若修复需要改变已批准的架构，先交给开发者决定，并按 `project-setup` 新增 ADR。不要通过删除失败检查、掩盖异常或编造测试结果来完成修复。
