# 质量检查

先确定审查范围和基准，再读实际差异、相关源文件、已确认的 ADR、项目规则与测试。检查需求是否完成、现有组件是否被无谓重复、模块边界是否偏移、错误与边界情况是否处理，以及交接记录是否与代码相符。优先报告有文件与行号依据、会影响行为或维护的具体问题；不要用泛泛建议淹没有效发现。

运行与改动相关且可用的项目检查。报告中逐项区分**通过、失败、未运行、工具不可用**，给出命令或审阅依据。没有 CLI 时可人工检查文档和代码，但不能称为 `soloweave check` 通过。不能把旧交接中的测试结果当成这次测试结果。

按影响程度列出问题、位置、理由与可执行的修复方向；没有发现问题时说明审查范围和剩余验证缺口。若本次审查推动了重要修复或准备切换 Agent，按 `project-continuity` 更新交接；该 Skill 未安装时直接更新项目已有文档。审查本身不授权提交、推送或发布。
