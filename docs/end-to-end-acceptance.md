## 完整项目场景与边界

使用从公开仓库安装的五项 Skill，在隔离临时目录运行真实 Codex CLI 0.162.0-alpha.17.2，沿用配置模型 gpt-6.1-sol。每个阶段是新的 ephemeral 会话，不携带旧聊天；目录文件保留。退出码不能代替行为审阅。

1. 普通需求：前后端分离、本机单用户、中文待办、熟悉 JavaScript、少依赖，支持新增／完成／删除及持久化；提示词没有点名 Skill。
2. 测试方批准第一阶段推荐的原生前端、Node 内置 HTTP 后端、本地 JSON 存储。本轮明确只实现新增／完成／持久化，删除留给下一会话。这个批准只针对测试项目，不是开发者对 SoloWeave 本身作技术选型。
3. 后续新会话只收到“请继续这个项目”，检查其是否从项目资料与实际代码定位并推进删除功能。

第一阶段实际读取入口、设置、功能与交接 Skill，按可组合维度给出推荐，记录待确认决定；确认前没有应用代码或已批准 ADR。

第二阶段实际读取上述四项，核对已有记录；批准后生成 ADR 与 PROJECT、STATUS、HANDOFF、CHANGES 四份上下文文件。代码只实现本轮范围，HANDOFF 明确“直接实现删除任务”，并指出应复用的保存队列及前端公共方法。实际直接服务验证覆盖新增、完成、并发写入、UTF-8 分块、数据落盘及重启恢复 14 个任务。

该会话的 `node --test` 两种执行方式均因 `spawn EPERM` 失败；Agent 没有把它写成通过，而是记录了直接服务验证通过、原自动测试受阻、浏览器检查未运行。测试方在独立保存的第一轮代码快照上，用允许子进程的环境重跑原集成测试：**2 项通过**。该外部结果不改写原会话的失败记录。

第三阶段只收到“请继续这个项目”，实际读取入口、交接与功能 Skill，核对项目上下文、ADR、代码和测试；没有笼统询问继续方向，直接完成已确定的删除任务。复用后端串行保存与前端 request/run/load，保持 ADR 不变，更新四份上下文文件。直接服务验证通过删除未完成与已完成任务、重复／未知 ID、并发混合写入；实际重启后 21 个保留任务与快照一致，已删任务未恢复。

该会话继续如实记录自动测试的 spawn EPERM，以及其浏览器接口不可用。测试方在最终快照独立重跑原集成测试：**2 项通过**。随后通过可用的本机浏览器真正点击新增、完成、删除，关闭标签页，停止并重启测试后端，再打开新标签页：完成状态保留，已删除任务未恢复。核对 JSON 落盘后，已停止两个专用测试服务。

**结论：本轮选型确认、持续开发与新会话接手场景通过。** 这不是所有项目类型或所有模型的完整覆盖；没有验证移动布局、浏览器失败交互或旧安装冲突。Agent 内部失败与测试方外部成功分别保留，不能混写。未单独重跑五项各自所有行为，质量 Skill 本轮仅验证公开安装与分发资源。
