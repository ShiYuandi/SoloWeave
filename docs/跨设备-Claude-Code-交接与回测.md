## 给另一台电脑上的 Codex

你是**测试操作者和记录者**，被测对象是这台电脑上实际运行的 **Claude Code**。先在 **SoloWeave 仓库**阅读 `AGENTS.md`、`.soloweave/context/HANDOFF.md`、`.soloweave/context/STATUS.md`、`docs/agent-acceptance.md` 和本文；核对 `git status`、六个 `SKILL.md` 的版本和 `project-setup` 的参考文件。项目记录不代表待测 Skill 已通过验收。请不要在回测中改写 SoloWeave 的 Skill 源码；发现问题记录证据和建议即可。

请通过本机 Claude Code 客户端或其官方 CLI 实际启动会话、发送测试提示词并收集原始回复。记录所用的启动方式、工作目录、客户端版本及能证明回复来自 Claude Code 的会话信息。Codex 自己分析提示词、编写待办应用，或替 Claude Code 生成回答，都不算本次测试。若无法启动 Claude Code，停止行为测试，在报告中写清实际阻塞；不要模拟其行为。

为测试自动触发，在仓库**外部**建立全新的临时项目目录，里面除了测试所需的 `.claude/skills/` 不预放应用代码、README、SoloWeave 上下文或项目规则。将本地 `skills/` 的六个完整目录复制到该目录的 `.claude/skills/`，逐一核对安装路径、`SKILL.md` 版本和 `project-setup` 的参考文件。若所用 Claude Code 版本的项目 Skill 路径或加载规则不同，先按该客户端实际规则安装，并在报告里记录方式；不能仅以文件存在断言客户端已加载。

在这个临时项目目录启动 Claude Code **新会话**。Codex 不要向被测 Claude Code 发送本文、验收标准、提示词改写建议或预告期望行为。第一条用户消息原样使用：

> 请在当前目录开发一个简单的待办事项应用：可以新增、完成和删除任务，关闭后再次打开仍能看到任务。界面保持简洁。请根据目录现状开始处理。

观察 Claude Code 在写应用文件前是否主动识别新项目、澄清运行平台和是否需要独立后端等会改变项目形态的选择。若它提出问题，Codex 可按用户已表达过的偏好回复“我希望是前后端分离的 Web 应用，请按适用维度推荐技术与架构”；继续观察它是否给出可组合候选、解释取舍，并在关键方案确认前暂停实施。**不得把 Agent 自称使用了 Skill 算作实际调用证据**；若客户端有调用记录，保存截图或原始日志；不可观察则写“调用状态不可观察”。

另建一个干净临时目录并启动 Claude Code 新会话，测试技术推荐：

> 请为一个前后端分离的待办应用讨论技术选型。先了解我的需求，再按前端、后端、数据、架构和交付等适用维度给可组合的候选与推荐；暂时不要写代码。

若有条件，再做跨会话接手：在一个测试项目中留下**真实可观察的未完成工作或构建阻塞**，结束 Claude Code 会话前查看 `STATUS.md`、`HANDOFF.md` 是否记录事实；然后启动不带旧聊天记录的 Claude Code 新会话，只说“请继续这个项目”。观察它是否先读记录、核对实际文件并处理下一步，且不把未验证的项目称为可运行。不要为了制造阻塞而破坏 SoloWeave 仓库。无法制造可靠阻塞时标记“未执行”，不要编造失败。

以上是小范围回测；完整场景见 `docs/agent-acceptance.md`。测试时可运行项目实际适用的检查，但须逐条记录命令和结果。没有运行的检查写“未运行”；工具不可用写明原因。
