# SoloWeave 项目设计

核对日期：2026-10-11。产品定位：面向个人开发者与 1–5 人团队的 AI 开发 Skills。

## 目标

开发者安装一次 Skills 后直接提出开发需求。AI 先了解项目与需求，在关键技术和架构选择上说明取舍并等待开发者确认；实施时复用已有代码、运行真实验证，并将进度和下一步留在项目中。更换账号、模型或客户端后，新会话可以从项目文件接手。

## 产品边界

- `skills/` 是六个 Skill 的唯一源码和发布来源，各项可独立安装，参考资料随完整目录安装。
- 用户通过支持 Agent Skills 的客户端使用。自动触发取决于客户端、描述与任务，不能保证每次触发；必要时可以明确点名。
- 技术和项目类型的示例用于发现适用维度，不限制 AI 推荐适合需求的方案。
- 维护者使用 PowerShell 7 脚本检查和打包。真实客户端回测独立执行，静态 CI 不代替模型行为测试。
- 尊重已有项目约定和用户修改；关键决定由开发者确认，提交、推送和公开发布遵循明确授权。

## 六个工作流

| Skill | 职责 |
| --- | --- |
| soloweave | 核对目录与项目事实，区分新旧项目并选择适用流程。 |
| project-setup | 澄清需求，按适用维度比较可组合方案，确认后记录决定。 |
| feature-workflow | 搜索并复用已有实现，完成功能、验证和记录。 |
| systematic-debugging | 复现失败，定位原因，最小修复后回归验证。 |
| quality-review | 根据实际文件和验证证据报告具体质量问题。 |
| project-continuity | 在任务节点或受阻时记录真实状态，新会话核对后继续。 |

缺少其他 Skill 时，当前 Skill 仍应完成必要步骤或遵循项目已有约定，不要求用户安装整套后才能工作。

## 项目记录

优先沿用目标项目已有的等价文档，需要建立持续记录时使用：

- `.soloweave/context/PROJECT.md`：稳定目标、主要模块、运行入口与已确认决定。
- `.soloweave/context/STATUS.md`：当前任务、已完成、阻塞与下一步。
- `.soloweave/context/CHANGES.md`：重要改动与涉及文件。
- `.soloweave/context/HANDOFF.md`：任务、最近修改、实际验证、风险、下一步、核对时间与 Git 状态。
- `.soloweave/decisions/ADR-NNNN.md`：关键决定、候选、理由、约束和开发者确认事实。

待确认内容不得记为已批准。接手时以实际文件、Git 和重跑结果核对记录；通过、失败、未运行与工具不可用分别记录。Git 不可用时明确说明，凭据只记录配置要求。简单文字修改适度记录，不强制建立复杂任务系统。

## 验收

1. 标准安装器发现全部六项，安装文件及参考资料与源码一致，更新前保留用户修改。
2. 新项目先澄清影响形态的缺口，关键选型确认前不直接实施。
3. 既有项目优先复用实现，故障修复先复现，审查结论有实际文件和验证依据。
4. 受阻时记录真实失败与未完成项，新会话从项目文件推进已知下一步。
5. 每项独立安装可用；真实调用、静态检查和安装核对分别记录。
6. 未实测的客户端、模型和场景明确保留待验证状态。
