# Skills 优先迁移实施计划

日期：2026-10-10。依据：[设计](skills-first-design.md)。

## 第一阶段：仓库可直接安装

1. 新建根目录 `skills/`，保留五个已发布名称，新增调试 Skill。为每个 Skill 写明触发条件、执行步骤、输出和异常处理；入口用于自动识别项目与任务。
2. 将本地 SkillHub 打包脚本改为读取根目录 `skills/`，不改变旧版 CLI 的嵌入资源。增加格式与目录检查，避免发布两个互相冲突的源目录。
3. 在隔离目录验证 Skill 发现、格式、打包和无 CLI 文件流程。可用时运行标准安装器的 `--list`，区分本地发现与真实远程安装。

## 第二阶段：默认体验与文档

4. 将中英文 README 的快速开始改为 Skills 安装和普通自然语言开发请求；将 Go CLI 放入旧版可选工具章节，说明它内置的是旧版 Skill 快照。
5. 更新中英文 Skills 使用指南、目录说明与验收步骤；记录哪些平台已实测，哪些仍待人工验证。
6. 在本仓库执行一次检查点，更新 `STATUS.md`、`HANDOFF.md` 和 `CHANGES.md`，只写实际运行的验证。

## 第三阶段：发布前与后续移除 Go

7. 公开更新前另行核对 SkillHub 的导入、版本和 slug；未经用户明确要求，不提交 commit、推送或发布。
8. 在真实 Codex、Claude Code、Cursor 客户端分别测试普通请求触发、重要决策确认、任务结束更新和跨账号恢复。逐项记录结果。
9. 纯 Skills 验收稳定后，再设计 Go CLI 的停更、迁出或删除；移除前保留旧版下载与迁移说明，不直接删除已有项目数据。

## 本轮完成条件

第一、二阶段的仓库文件和本地验证完成；第三阶段作为后续验收与发布任务。任何未实际运行的在线安装或客户端测试都标为待验证。

## 本轮执行记录

- 第一阶段文件与打包完成；六个 ZIP 和 SHA256SUMS 已在本地核对，Go 旧版测试、静态检查与构建通过。
- 标准安装器首次尝试遇到 npm 连接拒绝，重试后 `add . --list` 发现六个 Skill；临时项目的 Codex、Claude Code、Cursor 安装完成，安装后的文件与根目录源文件一致。Windows 默认安装模式也完成了 Codex 六个文件的安装。`quick_validate.py` 因缺少 PyYAML 未完成；仓库打包脚本提供了名称、字段、版本与 slug 的本地校验。
- 无 Go CLI、无 Git 的临时项目完成一次人工开发演练：测试先失败，复用已有函数后两项检查通过，项目状态与交接文件可供单独读取和复测。此结果不代表真实 Agent 自动触发通过。
- 第二阶段的中英文公开文档已改为 Skills 优先；真实 Agent 自动触发和跨客户端恢复仍需独立验收。

## 下一轮实施顺序

1. 本轮改动推送后，从公开 GitHub 地址运行标准安装器的发现与隔离安装，核对六个名称、版本、路径及内容；发现与本地源文件不同步时先修复发布入口。
2. 用真实 Codex 客户端在干净的临时项目测试普通开发请求能否自动使用入口 Skill，再测试技术选型待确认、功能或修复后的交接、无旧聊天记录的恢复。逐项保存实际提示词、观察结果和版本；手动点名 Skill 的结果单独记录。
3. 在可用的 Claude Code 与 Cursor 客户端重复关键场景，区分已安装文件与真实运行效果。若本机没有对应客户端，保留待验证状态，不以文件检查代替。
4. 核对 SkillHub 从 GitHub 导入时的根目录、六个 slug 与版本及旧版兼容关系，再按单独的发布要求更新平台；发布后检查公开页面展示的正文与版本。
5. 纯 Skills 流程稳定后，再制定旧 Go CLI 的停更和迁移方案，保持已发布下载与现有用户资料可用。
