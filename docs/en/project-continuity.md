# Project continuity

[简体中文](../project-continuity.md)

Keep context in project files, reusing existing documentation where possible. Default locations are described in [project records](configuration.md).

After meaningful work, a blocker, or a handoff, record the current task, changed files, actual commands and results, unresolved issues, next steps, verification time, and available Git state.

Distinguish passed, failed, not run, and unavailable tools. A permissions denial is not a build result. State when Git is unavailable and keep credentials out of records.

On “continue this project,” read goals, status, handoff, and ADRs, then verify actual files and Git. Advance a known next step; ask when a necessary decision or goal is missing. Current files take precedence over stale notes.

Skills maintain Markdown records rather than machine checkpoints. See the [workflow](skill-only-workflow.md) and [legacy migration](cli-migration.md).
